## Why
当前运行只能产出单一输出(通常是详情表),无法在同一次运行内生成分析/汇总表,导致:
- 详情与分析需要二次离线处理,链路断裂
- 无法在同一报表包中同时交付明细与结论
- 进度与可观测性事件无法驱动下游分析

**核心示例(必须支持):**
- 详情表: 订单ID、订单金额、订单利润、供应商ID(按批次输出)
- 汇总表: 供应商ID、利润率(基于详情表聚合)

**类似示例(可用不同方式实现):**
- 用户访问明细 → 渠道/日期汇总(用于营销分析)
- 库存流水明细 → 仓库库存余额(用于运营看板)
- 退款明细 → 退款原因占比与异常告警
- 物流明细 → 线路/承运商时效统计
- 交易明细 → Top-K 商品/供应商排行(需要可合并/近似算法)
- 订单明细 → 精确分位数/分桶统计(需要后置聚合)

## What Changes
- 引入“多输出组合”能力: 单次运行可定义多个输出目标(详情+汇总),可写入同一容器(如同一 workbook 的多 sheet)或独立输出.
- 引入“派生输出”能力: 允许在同一次运行中对详情流进行增量聚合并产出汇总表,支持批次级累计与最终收尾输出.
- v1 仅提供 IR/Python 配置入口,不改动 YAML DSL;文档中说明未来 DSL 的潜在映射.
- 明确对单输出路径的兼容性影响范围,并提供清晰的失败策略与资源控制口径.

## Impact
- 受影响规范: 新增 output-composition、derived-outputs.
- 涉及组件: 执行流程、输出组合与容器、派生计算与聚合、可观测事件对齐.
- 主要风险: 内存增长、输出顺序一致性、并行模式下的可重复性.

## Compatibility Notes (adaptive-execution-mode)

- thread/process 批次级并行将被移除,执行并发语义收敛为 `seq|adaptive`;本 change 中关于“并行模式下可重复性”的讨论应以 `adaptive` 的批次内并发与提交点回放为主要并发形态.
