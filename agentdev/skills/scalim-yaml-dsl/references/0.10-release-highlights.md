# 0.10.0 版本亮点（agent）

## 何时读取

- 用户从 ≤0.9 升到 0.10，问「要不要改 YAML / 默认变了什么」
- 写发版说明、评估 `lookup_chunk_size` + adaptive 是否该开分片并行
- 人类文档总览：`docs/doc/releases/0.10.0.md`

## 硬结论（先说）

- **YAML authoring 主线无强制迁移**（本批不是 breaking upgrades 索引里的字段删除类变更）。
- 若 validate 因旧字段失败，仍走 `references/upgrades/*.md`（book write / budget / xlsx kinds 等）。
- 性能相关三项：

| 能力 | 默认 | 开关位置 |
|------|------|----------|
| write-precompute | 开 | 无总开关；规划期 `late_fields` |
| row-wise fusion | 开（安全外壳内） | 无总开关 |
| lookup chunk 并行 | 关 | Python：`parallelize_lookup_chunks` + `parallel_mode=adaptive` |

## 适配注意

### write-precompute

- 只写出、无下游消费者的派生可能不再在 Compute 段物化进 `BatchContext`。
- 旁路若假设「算完就在 context」→ 改调用侧或让字段被其它派生/LoadRef 消费。
- `FIELD_COMPUTE` 可能带 `meta.scalim_compute_phase`。

### row-wise fusion

- 同段 + deps 完全相同才融合；`calc_calls` 仍 `N×M`。
- 列 sink / 订阅 `FIELD_COMPUTE`|`OPERATOR_SPAN` / `fast_fail` / EXP memo 等 → 不融合。

### lookup chunk 并行

- `lookup_chunk_size` **只**表示分片大小，**不是**并行开关。
- 启用示例：

```python
from scalim.dsl.yaml_dsl import DemandRunRuntimeOptions

DemandRunRuntimeOptions(
    parallel_mode="adaptive",
    parallelize_lookup_chunks=True,
    max_workers=8,
    max_chunk_workers=None,
)
```

- `seq` 永不分片并行；在途帽 = resolved adaptive workers `W`。
- `loader_call.chunk_offset`；完成序；退化层下回调 MAY 在 chunk worker 线程（订阅方须线程安全）。
- 错误路径 calls MAY > 串行；成功路径相等；无半份 cache。
