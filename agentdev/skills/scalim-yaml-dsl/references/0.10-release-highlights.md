# 0.10.0 版本亮点（agent）

## 何时读取

- 用户从 ≤0.9 升到 0.10，问「默认变了什么 / 要不要改 YAML」
- 写发版说明、评估 keys 分片 + adaptive 是否该开片间并行
- 人类文档总览：`docs/doc/releases/0.10.0/index.md`

## 硬结论（先说）

- **0.10.0 当时**：性能三项不要求 YAML 字段迁移（write-precompute / fusion 默认开；chunk 并行 Python opt-in）。
- **c40（0.10.* 后续）**：YAML `sources.*.lookup_chunk_size` **已迁出** → Python `LookupChunking`；再写会 fail-fast。下游若仍带该字段，先扫 YAML 并改 Python。升级卡：`references/upgrades/2026-08-09-lookup-chunking-python-ssot.md`。
- 若 validate 因其它旧字段失败，仍走 `references/upgrades/*.md`（book write / budget / xlsx kinds 等）。

| 能力 | 默认 | 开关位置 |
|------|------|----------|
| write-precompute | 开 | 无总开关；规划期 `late_fields` |
| row-wise fusion | 开（安全外壳内） | 无总开关 |
| lookup chunking / 片间并行 | 不分片；并行关 | Python：`LookupChunking.sized(N[, parallel=True])` + `parallel_mode=adaptive`（遗留 `parallelize_lookup_chunks` 仅兼容） |

## 适配注意

### write-precompute

- 只写出、无下游消费者的派生可能不再在 Compute 段物化进 `BatchContext`。
- 旁路若假设「算完就在 context」→ 改调用侧或让字段被其它派生/LoadRef 消费。
- `FIELD_COMPUTE` 可能带 `meta.scalim_compute_phase`。

### row-wise fusion

- 同段 + deps 完全相同才融合；`calc_calls` 仍 `N×M`。
- 列 sink / 订阅 `FIELD_COMPUTE`|`OPERATOR_SPAN` / `fast_fail` / EXP `call_by` memo 等 → 不融合。
- **`VizObserverConfig(trace_enabled=True)` 也会关掉 fusion**(订阅高频 `FIELD_COMPUTE`);对拍 fusion 请关 trace。详见 `docs/doc/viz/scalim-viz.md`。

### lookup chunking / 片间并行

- YAML **不要**再写 `lookup_chunk_size`（c40）。
- `LookupChunking.sized(size=...)` **alone 不是并行开关**；并行写 `sized(..., parallel=True)` 且须 `parallel_mode=adaptive`。
- 启用示例：

```python
from scalim.dsl.yaml_dsl import DemandRunRuntimeOptions, LookupChunking

DemandRunRuntimeOptions(
    parallel_mode="adaptive",
    max_workers=8,
    lookup_chunking={
        "customers": LookupChunking.sized(800, parallel=True),
    },
)
```

- `seq` 永不分片并行；在途帽 = resolved adaptive workers `W`。
- `loader_call.chunk_offset`；完成序；退化层下回调 MAY 在 chunk worker 线程（订阅方须线程安全）。
- 错误路径 calls MAY > 串行；成功路径相等；无半份 cache。
